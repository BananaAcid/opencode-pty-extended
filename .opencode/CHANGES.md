- **[bugfix] — /pty-config, first live TUI test**: user reported every interaction dead + broken layout. Fixes in `tui.tsx` only (PATCH_VERSION/package stay 1.14.0.44):
  1. **Reactivity**: the dialog body is now wrapped in `createRoot` at the `/pty-config` call site — `dialog.show(() => <…/>)` calls its factory once with no reactive owner, so every signal read in the JSX snapped once and nothing ever re-rendered (dead arrows, dead search, dead folds). A module-scoped `disposeRoot` + `closeDialog()` tears the root down on ALL close paths (esc, close button, after save); re-showing disposes a stale root first. ConfigDialog routes its closes through a new `onClose` prop (`close()` helper).
  2. **Mouse**: all handlers moved from `<box>` rows onto `<text>` (OpenTUI hit-testing fires on the deepest `text`; box handlers never fire) — each row is now ONE fixed-column `text` line with one handler (left = set cursor + activate, right = set cursor + clear); the save/close buttons' handlers moved to their inner `<text>` as well; the search row (label + fallback text) is clickable.
  3. **Windowing**: rewritten as a flat-line window over the whole item list (headers cost one line) — the old "sticky header" slice dropped every mid-window section header, which is why the user saw only `▼ general (3)` with all rows under it; when the window starts mid-section, that section's header now repeats at the top. Verified in isolation: `cfgtest/window-test.mjs` 73/73.
  4. **Cursor**: all reads go through a clamped `cursorIdx` memo so folds/search filtering can't strand the cursor past the end.
